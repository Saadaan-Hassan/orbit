# Governance

## This project is not actively maintained

There is no one triaging issues, reviewing pull requests, or making
architectural decisions on an ongoing basis. [Saadaan
Hassan](https://github.com/Saadaan-Hassan) built Orbit and published it as
open source for others to use, learn from, or build on — not as the start
of an actively governed community project. That may change in the future,
but don't expect it to.

## What this means in practice

- **Pull requests**: may not be reviewed or merged, regardless of quality.
  Fork the repo if you want your changes to live somewhere they'll
  definitely be kept.
- **Issues**: may not get a response. See [`SUPPORT.md`](SUPPORT.md) and
  [`SECURITY.md`](SECURITY.md) for what little process exists.
- **Architectural decisions**: nobody is making them going forward. The
  decisions already made, and why, are recorded in `AGENTS.md` and
  `OPEN_SOURCE_ROADMAP.md` — that history stands as-is; there's no active
  process for changing it.
- **Becoming a maintainer**: there's no process for this. If you want to
  take over stewardship of a fork, that's your own project at that point,
  governed however you choose.

## If you want to build on this instead

That's explicitly what this repo is for. Fork it, rename it, take it in a
different direction — the Apache-2.0 license permits it and no permission
is needed. `AGENTS.md` and the `docs/` directory describe the architecture
and decisions as they stood when development paused, which should be
enough to orient yourself without the original author.

## Changes to this document

This describes the project as it actually is. If active maintenance
resumes at some point, this file should be rewritten to match — it isn't
meant to be aspirational either way.
